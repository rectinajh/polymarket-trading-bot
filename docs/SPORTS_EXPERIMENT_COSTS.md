## 一、RN1 为啥能赚钱？（听得懂版）

**一句话：RN1 不是靠「猜哪队赢」，是靠「Polymarket 足球盘标价标错了，它当收租的庄家」。**

### 1. 它实际在干嘛

| 普通人以为 | RN1 实际 |
|---|---|
| 预测大神，猜比分 | **91% 时间在挂单等人来卖**（Maker），不是追价猛买 |
| 赢一场吃一场 | **88% 仓位拿到比赛结束再赎回**，几乎不卖 |
| 大单豪赌 | 中位单笔约 **$17**，小额、高频、分散 |

可以把它想成：**在欧洲足球比赛时段，在 YES/NO 两边挂「收购价」，散户急着卖就卖给它；它赚中间的价差 + 价格标错的那一点。**

链上数据（[Foresight 逆向文](https://foresightnews.pro/article/detail/95050)）：53 万笔 Maker 买入，Maker 卖出只有 64 笔——**几乎只买不卖，像开「小保险公司」收保费。**

### 2. 「定价标错了」是什么意思

Polymarket 足球常是一个问题一个盘：「A 队赢吗？YES/NO」。  
传统博彩一个盘里 Win/Draw/Lose 一起定；Polymarket 多个独立盘，**每个盘都带一层手续费摩擦**，叠在一起会让：

- **热门（大概率会赢的）** → 标价 **偏低**（实际赢面 &gt; 价格暗示的赢面）
- **冷门（小概率爆冷）** → 标价 **偏高**（散户爱买「彩票」）

学术名叫 **Favorite–Longshot Bias（热门–冷门偏差）**。  
RN1 文章里的数据例子：

- 入场价 **0.60–0.70**（市场说约 65% 会赢）→ 实际赢约 **80%**
- 入场价 **0.70–0.80** → 实际赢约 **89%**

所以它 **不需要知道今晚谁进球**，只需要知道：「这个热门现在标 0.65，历史统计像 0.80」→ 长期有 edge。

### 3. 为啥这个「标错」可能长期存在

1. **产品结构**：独立二元盘 + 多层 vig，热门被系统性压价。  
2. **散户行为**：更愿意花 $5 博 10 倍冷门，不愿花 $70 博 1.4 倍热门 → 冷门贵、热门便宜。  
3. **不是某一场球的情绪**：是 **市场结构 + 人群行为**，所以文章说偏差 **到现在还在**。

### 4. RN1 还多了什么过滤

- **只做欧洲足球**（英超、意甲、法甲、西甲等，文章验证联赛 ROI 都为正）
- **只做热门区间**（约 0.50–0.85）
- **用 Pinnacle 当尺子**：全球较准的博彩参考；只有 Polymarket **明显比 Pinnacle 便宜** 才动手

### 5. Pinnacle 是啥？

**Pinnacle（平博）** 是全球公认 **赔率最准** 的传统体育博彩公司之一。

| 特点 | 说明 |
|---|---|
| 低抽水 | 约 **~2%**（行业常见 5～10%） |
| 不限赢家 | 不因为你会赢就封号 |
| 结果 | 聪明钱集中 → 赔率被反复修正 → **接近真实概率** |

量化圈常把 Pinnacle 当 **「基准线 / 真值尺子」**——类似金融里的中间价，不一定 100% 对，但市场公认最难骗。

**RN1 怎么用：** 先看 Pinnacle 认为某队赢的概率（如 **75%**），再看 Polymarket 标多少（如 **65%**）。差距 = edge；**有差距才做，没有就不做**。

### 6. RN1 是「稳定套利」吗？风险最小吗？

**不是。** RN1 是 **统计上正期望**，不是无风险套利；风险大约 **3～4 / 5**，不是最低的。

| 维度 | ② Completeness（你们在跑） | ③ RN1 体育 Maker |
|---|---|---|
| 赚什么 | YES+NO **加起来 &lt; $1**，锁 $1 结算 | 热门 **统计上** 被低估 + spread |
| 有没有方向 | **无方向**（谁赢都赚，两腿都成交时） | **有方向**（结算只有一边赢） |
| 为啥赚 | 数学锁死：花 $0.97 → 结算 $1 | **统计规律**：标 0.65 的球队历史实际赢 ~80% |
| 单笔会亏吗 | **不亏**（两腿都成交） | **会**（那场冷门赢了，热门侧归零） |
| 风险 | **1～2**（主要怕第二腿失败） | **3～4** |
| 怎么赚钱 | 价差直接锁定 | **大量比赛** 分散，赢多输少 |

**人话：**

- **② = 捡到两张互补彩票，合起来包赚** → 真套利，风险最小，但 Polymarket 上常被秒光（你们 0 笔）。
- **③ = 开保险公司，只保大概率事件** → 多数收「保费」，偶尔赔一单；**100 场里赢 80、亏 20，总账为正**，不是每笔都赚。

详见 [STRATEGY_MODES_AND_LEARNING.md](STRATEGY_MODES_AND_LEARNING.md) 模式 ② vs ③ 对照。

### 7. 鸡蛋类比（再白话一遍）

> **菜市场卖鸡蛋**
>
> - 好鸡蛋（热门队赢）真实值 **$1.00**
> - Polymarket 把好鸡蛋标成 **$0.65**（结构 + 散户买冷门把热门压价）
> - 冷门鸡蛋标 **$0.35**（太贵，赌徒爱买彩票）
> - RN1：**$0.65 收好鸡蛋**，等结算 → 约 **80%** 拿回 $1.00
> - 赚：$0.65 → $1.00 的 **$0.35**（多数时候）
> - 亏：**20%** 好鸡蛋碎了（冷门赢）→ $0.65 **归零**

**粗算期望（说明「统计赚钱」而非「无风险」）：**

- 赢：$0.35 × 80% ≈ **+$0.28**
- 亏：$0.65 × 20% ≈ **−$0.13**
- 净期望 ≈ **+$0.15 / 笔**（约 23% ROI）——需 **很多场** 才收敛；**单场仍可能全亏**。

**为啥不是无风险：**

1. Pinnacle / 历史统计也会错  
2. 单场冷门 → 本金归零  
3. Maker 被进球前「更懂球的人」吃单（adverse selection）  
4. 要 **几百场** 样本，统计才可靠

## 二、月榜前三在赚什么？和 RN1 像不像？

来源：[Polymarket 月榜盈亏](https://polymarket.com/zh/leaderboard/overall/monthly/profit)。

| 排名 | 大致画像 | 和 RN1 像吗 |
|---|---|---|
| **#1 sainttroplay** | 足球大单；单场阿森纳相关可 **+$180 万** 级别 | **品类像**（足球），**打法不太像**——更像 **大赛事上大仓位 event 交易**，不是中位 $17 做市 |
| **#2 网球地址** | ATP 等 **单场赛事** 盈利 | **品类像**（体育 event），**打法偏「押结果」**，不是 RN1 那种双边 Maker |
| **#3 超高成交量** | 月成交 **$7,341 万**，利润 **+$126 万**（粗算 turnover ROI ~**1.7%**） | **换手风格更像** RN1/系统盘——**薄 edge × 巨量**，不是一单暴富 |

**RN1 自己在榜上大约 **Top 11** 一档（月利润 +$51 万、月成交 ~$8,185 万量级），不是 #1，但和 #3 同属「体育池子里系统化赚钱」这一路。

### 一张关系图（粗分）

```text
Polymarket 体育/event 赚钱者
├── A. 大单 event / 信息速度型     ← 月榜 #1 #2 的公开大单更像这类
├── B. 高换手 Maker + 结构性偏差   ← RN1 文章描述的核心（#11 附近）
└── C. 极高 volume、薄 ROI 系统盘   ← 月榜 #3 体量更像这类
```

**结论（听得懂版）：**

- **都在体育/event 大池子里捞钱** —— 所以榜上和 RN1 **品类差不多**。
- **具体打法不一定一样** —— #1 像「大赛事上大注」；RN1 像「整场开个小交易所收 spread + 吃热门标价错误」；#3 像「机器疯狂刷单赚薄利」。
- **不能等于「学 RN1 = 复制榜前三」** —— 榜单是 **结果**，背后至少三种工种。

## 三、为啥我们 Conservative 榜上看不见，但不等于错了？

| | Conservative（你们现在在跑） | RN1 / 月榜前列 |
|---|---|---|
| 玩什么 | 天气 NO、Completeness（YES+NO&lt;$1） | **足球、网球、电竞** |
| 怎么下单 | **FOK 吃 ask**（Taker） | **91% Maker 挂单** |
| 扫描 | 每 **5 分钟** | 比赛时段 **秒级** |
| 资金 | ~**$119** | 月成交 **百万～千万美元** |
| 逻辑 | 有 **≥2¢ edge** 才买贵 NO | 吃 **结构性热门偏差 + spread** |

**排行榜是大池子 + 大资金 + 专业执行的记分牌**；Conservative 是 **小资金、低工程、等非体育 mispricing**，本来就不会显眼。

类比：榜上是连锁快餐总部财报；你们是小饭馆——不在财报里，不代表饭馆一定开不下去。

## 五、要不要做体育实验？我们讨论过的结论

### 可以做对比，但不建议「$100 + 整套新代码 + 实盘」当科学实验

| 做法 | 建议 |
|---|---|
| 新 Polymarket 地址 + 独立进程 | ✅ **隔离方式对** |
| 初始 $100 | ⚠️ 当 **学费上限**；很难得出「哪条路线更优」的统计结论 |
| **完全另起一套代码库** | ❌ **没必要**；同 repo 加 `sports` 模块 + 第二 PM2 即可 |
| 和 Conservative 比利润 | 要 **≥60 天、几十笔已结算**，比 **ROI、回撤、笔数**，不只比谁钱多 |

### 推荐路径（由轻到重）

1. **阶段 0（1～2 周）**：只研究 —— 看 RN1 主页、读 Foresight 文、弄清 A/B/C 三种体育打法。  
2. **阶段 1（4～8 周）**：新地址 **paper / 信号日志** —— 有 Pinnacle（或同类）价差才记「本会下单」，不下单。  
3. **阶段 2（可选）**：**$500～1000** + 最小 bot（同 repo、第二 PM2），硬 cap 本金。  
4. **阶段 3（60～90 天）**：与 Conservative 并排台账，到点 **写死停止**（如亏 30% 或满 90 天）。

**$100 能验证的是「流程会不会跑」**，不是「体育是否优于 Conservative」。

## 六、若做体育：三档目标（成本差一个数量级）

先定打哪一档，再谈花多少钱：

| 档位 | 目标 | 和 RN1 的关系 |
|---|---|---|
| **L0 认知** | 手动或观察，验证有没有信号 | 不是竞争，是学费 |

| **L2 认真做市** | WebSocket、Maker 双边、外部赔率、欧足时段自动化 | 接近 RN1 描述，仍差资金与排队 |
| **L3 榜单级** | 毫秒、多市场、团队运维 | 机构投入；$100 不在讨论范围 |

## 七、各方面成本清单

### 7.1 资金

| 项目 | L0 | L1 | L2 |
|---|---:|---:|---:|
| 实验本金 | $100 | $500～2,000 | $5,000～50,000+ |
| 可接受亏损 | 全亏 | 建议 20～30% 停 | 有 drawdown 规则 |
| Maker 冻结 | — | 挂单占 USDC，可用余额 **小于账面** | 同左 |
| 最小下单 | ~$1/笔 | 同左 | 同左 |
| Gas（MATIC） | ~$1～5/月 | ~$5～20 | 视链上操作 |

### 7.2 硬件 / 云

| 项目 | 说明 | 月费粗算 |
|---|---|---|
| 服务器 | L0 现有 VPS；L1+ 建议 **美国东部**（靠近 CLOB） | $0～80 |
| **地理延迟** | 亚洲 RTT 常 +100～200ms；**换语言救不了这个** | 美东 VPS 比 Go/Rust 优先 |
| 备用/告警 | L2 比赛日宕机 = 裸持仓 | 可选 |

### 7.3 软件 / 数据

| 项目 | 必需？ | 月费粗算 | 说明 |
|---|---|---:|---|
| Polymarket 账户 | 是 | $0 | 独立地址、独立 `.env` |
| **Sharp 赔率**（Pinnacle 等） | L2 强烈建议 | $0～500+ | RN1 核心；无参考线易退化成普通下注 |
| The Odds API 等 | L1 可替代 | $0～200 | 覆盖/延迟通常弱于 sharp |
| Polygon RPC | L1+ 建议 | $0～199 | 高峰可能限流 |
| 监控（Telegram 等） | L1+ | $0～50 | 欧足 UTC 17–23 建议有人/告警 |
| Gurobi / 跨市场优化 | 仅组合套利 | $$$ | 体育 FLB **不需要** |

### 7.4 代码：要不要重写？Python vs Go/Rust？

| 模块 | 建议 |
|---|---|
| `polymarket_client` / `gamma_client` | **复用** |
| `capital_policy` | **改参数复用**（sleeve cap、daily log 独立文件） |
| `safe_compounder` | **不复用**（体育要 **包含** 而非 SKIP） |
| 新模块 | `sports/` 策略 + 赛程 + 赔率适配 + Maker 库存 |
| 整库重写 | **不要** |
| Go/Rust | **L2 之前都不需要**；瓶颈多在 **网络 RTT、排队、资金**，不是 Python 慢 2ms |

**工作量粗算：** 新增约 **40～60% 代码**；L1 MVP 约 **2～4 周**业余；L2 Maker 常 **1～3 月+**。

### 7.5 人力 / 运维（隐性大成本）

- 欧足 **UTC 17–23** 是 RN1 高峰；不是「PM2 每 5 分钟扫一次」就完事。  
- **Adverse selection**：进球前 informed 用户吃你的 Maker 单——做市最隐蔽的亏法。  
- Proxy 钱包（`signature_type=3`）：结算赎回常需 **Polymarket UI**，bot 不能链上 redeem（见 CHANGELOG 赎回说明）。
